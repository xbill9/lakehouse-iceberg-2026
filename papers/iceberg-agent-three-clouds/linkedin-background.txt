Background for a LinkedIn post about "Four Iceberg Tools, Three Agent Frameworks".
Plain text on purpose: LinkedIn renders no markdown. Figures are from
evidence/matrix-summary.txt and evidence/derived-figures.txt, measured 2026-09-15.


THE SETUP

Companies keep big tables of data - spreadsheets with millions of rows - in a
standard format called Apache Iceberg. The point of a standard format is that any
tool can read it, whichever cloud it lives on.

Each big cloud (Google, Amazon, Microsoft) now also sells its own toolkit for
building AI agents: chatbots that can go and look things up for you.


THE QUESTION

If I build an AI helper that answers questions about my data, and I build it with
Google's toolkit, can I move it to Amazon or Microsoft without starting over?


WHAT I BUILT

One small AI helper whose only job is to answer questions about a data table. It
has four tools - basically four buttons it can press: list the tables, describe
one, count its rows, and read its rows.

Then I built that same helper three times, once with each company's toolkit:
Google ADK, AWS Strands and Microsoft Agent Framework. The buttons and the
instructions are identical. Only the toolkit and the AI model underneath change.


WHAT I MEASURED

I asked all three the same questions, three times each, and checked:
- Did it get the right answer? I look up the real answer myself, straight from the
  data, with no AI involved.
- Did it say where the answer came from? Every answer has to name the exact version
  of the table it read, so anyone can check it.
- How long did it take?


WHAT I FOUND

- The code barely changes between toolkits: a few lines of setup differ.
- Answers took about 4x longer on the slowest helper than the fastest. When I swapped
  models inside the same toolkit, the AI model (and the endpoint serving it) decided
  the speed, not the toolkit.
- They behave differently while working: one shows each button it presses, one
  prints every answer twice, one only shows the final answer.
- The hard part is not the AI. It is the plumbing underneath: each cloud needs
  different settings and credentials just to open the data files. That is the part
  that does not move between clouds.
- Once that plumbing is written, it works. Asked a question that forces them to open
  the data files on their own cloud, all three helpers read their data. Google's and
  Microsoft's answered correctly every time; Amazon's found the largest value every
  time but miscounted rows every time.


WHY SO CAREFUL

Articles that compare cloud companies get picked apart. So every number in the
article is produced by a script from saved results, every answer is checked against
the data itself, and anyone can re-run the whole thing from the repo.
