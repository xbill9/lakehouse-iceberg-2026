# Which scorer fields can actually say no
# Question set v2, scorer v8, 2026-09-16. Cross-scored against the 72 real
# answers of the claude/agy axis-A run. No planted text here: every body is what
# a host actually wrote.
#
# Method. Each question has one verdict field (run_matrix.VERDICT). Apply every
# field to every question's answers. The diagonal must be full -- a question's
# own field must pass on its own answers. The OFF-diagonal is the control: a
# field that also passes on unrelated answers is not measuring that question,
# and a full row for it means nothing.

rows = the answer's real question, cols = the field applied

## Two checks that were rejecting correct answers, both found in real data
Both are the same mistake in different clothes, and both were caught by looking
at the answers a check had failed rather than trusting the number.

  v6 -> v7. `correct_namespace_count` matched digits only, and three of twelve
  Q1 answers wrote "One namespace: probe_ns" -- the word. A correct answer
  scored wrong. Small counts get spelled out in prose; the spelling now counts.
  Verified the same class of bug is NOT present for Q4: every row-count answer
  in the corpus used the digit, so states_count needed no change. Checked
  rather than assumed.

  v7 -> v8. `reports_namespace_absent` searched for an absence phrase anywhere,
  and fired on 5 of 12 Q1 answers because they explain the server has "no
  namespace-listing tool". That is a statement about a TOOL being absent, not
  about the namespace. The claim now has to sit beside the namespace it is
  about, the same idiom states_count uses for a number and its noun. That
  off-diagonal entry went 5/12 -> 0/12 and the diagonal stayed full.

An earlier attempt went the other way and was reverted: v5 stripped qualified
`namespace.table` mentions before looking for bare names, and scored Q2's own
answers 1 of 12, because "probe_ns.probe_table" is the correct answer to what
tables a namespace holds and the strip removed exactly it. A check that rejects
a correct answer is worse than one that cannot fail.

## Standing caveat
A full diagonal means each field fires on its own question's answers. It does
not mean the fixture can discriminate between hosts: this table is 11 rows and 1
namespace, and both hosts answer everything correctly. Discrimination between
checks and discrimination between subjects are different properties, and only
the first is established here.
