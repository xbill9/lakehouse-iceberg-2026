## Result
Nothing moved. Every check passes on both transports, on both legs, on both
questions, on a local catalog and on a cloud one. The medians differ by less
than the spread inside either column.

The cost of MCP is not in what the agent does. It is in the code around the
agent, measured separately in mcp-per-framework.txt: three frameworks, three
shapes of build(), and a three-way branch in run_mcp.py that run_once.py never
needed.

Strands on Nova Micro answers in two calls either way. ADK on Gemini takes
longer and is more variable on both transports, and BigLake is slower than the
local Polaris on both -- each of those moves with the model or the catalog, and
the imported and MCP columns move together.

## Grading
Each catalog is graded against its own ground truth, read from that catalog by
iceberg-mcp-hosts/ground_truth.py. Polaris and BigLake hold the same fixture but
are different physical tables with different snapshot ids and metadata
locations, so one shared file would mark every BigLake citation wrong by
construction.

Both transports launch with the same environment and the catalogs file pinned
absolutely. A run that ends in a launch error, a catalog error, or in under a
second is recorded as failed rather than scored: a leg that could not start did
not answer badly. run_mcp.py refuses to start at all on an MCP SDK outside the
range every framework pins, so a version change cannot arrive as a wrong answer.

## Scope
Three runs per cell. Enough to say the columns match; not enough to put a number
on the difference between them.

Two legs of three. The azure leg discovers its four tools over MCP -- confirmed
-- and wants FOUNDRY_PROJECT_ENDPOINT to answer, so it is absent rather than
scored. The aws leg ran on the Polaris control; its Glue arm needs an AWS session
that has since expired, and is not included.
